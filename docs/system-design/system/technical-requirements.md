## 概述（Admin Center 与 UAM 的分工、交互流程）

- **Admin Center（管理中心）**：接入层中的 **Web Server**，面向运维人员的浏览器入口。提供登录页、**User Manager（用户管理）** 与 **Session Manager（会话管理）** 两个管理界面，并在桌面、平板、手机上自适应。登录成功后，浏览器对它的访问**基于会话**（cookie 中的 session id）。它自己**不保存密码，也不保存用户、账号、会话数据**。
- **UAM（User Account Management，用户账号管理服务）**：**RESTful 的领域服务**，用户、账号、会话的**唯一权威**。负责校验登录凭据、签发并管理会话、维护用户与账号，并对客户端提供这些数据的查询与管理操作。对 UAM 的访问**不基于用户会话**：它不使用 cookie、会话标识或任何用户凭据来识别客户端；**它目前也不识别调用它的服务**（没有服务密钥或其他服务间凭据，服务身份后续另行实现），只靠网络边界（仅内网、仅 Admin Center 可达）保护；客户端把「操作人是谁」作为请求数据传入。

**交互流程**（来自参考图二）：

1. 浏览器携带 **cookie 中的 session id** 请求 Admin Center（Admin Center 一侧是基于会话的访问）。
2. Admin Center 向 UAM **校验 session id**，UAM 返回**会话数据**（用户、账号、会话引用、到期信息）。session id 只作为「校验会话」「退出」的**输入数据**出现。（参考图中这里是 JWT；本规格不把它用作访问 UAM 的凭据，见 Clarifications。）
3. Admin Center 此后代表该登录者向 UAM 发起服务调用（查询与管理操作）时，把**操作人**（用户、账号、会话引用）作为请求数据明确传给 UAM。UAM 一侧是**无会话、不使用用户凭据、也不校验调用方身份的 RESTful 访问**（调用方由网络边界限定为 Admin Center）。
4. 浏览器始终只持有 session id，**拿不到会话数据本身**。

## Clarifications（技术性问答）

- Q: UAM 的网络范围是什么？ → A: UAM（领域服务）只在内网访问（已确认）；浏览器、公网与第三方碰不到 UAM。
- Q: UAM 要不要识别并限定客户端（服务间凭据）？ → A: 暂不要（已确认，**取代**此前「要，做静态服务密钥」的回答）：移除 clients 功能——不再有服务密钥、客户端清单、客户端权限与密钥轮换；UAM 目前不认证调用方，只靠网络边界（UAM 只对 Admin Center 实例开放，如 k8s NetworkPolicy / 内网）保护。服务身份（mTLS、平台身份、OAuth2 客户端凭据等）后续作为独立特性实现，届时再补认证。
- Q: UAM 要不要自己校验用户身份（把 UAM 当作接入层的、基于会话的服务）？ → A: 不要（已确认）：UAM 维持领域服务，不使用任何用户凭据，操作人由客户端以请求头传入。
- Q: 用户会话数据要不要用 JWT 作为访问 UAM 的凭据？ → A: 不用（已确认）。UAM 不基于用户会话，所以不使用用户凭据；它目前也不识别调用它的服务（服务身份后续另行实现）。操作人（用户、账号、会话引用）由客户端作为请求数据传给 UAM。
- Q: 调用 UAM 的服务用什么术语？ → A: 曾定为「客户端（Client）」；clients 功能移除后，UAM 里不再有该概念与相应标识符（`client_unauthenticated`、`UAM_CLIENTS`、`clientId` 已删除；`client_forbidden` 见下一条）。文中「客户端」仅作口语，指调用 UAM 的服务（Admin Center），不是浏览器。
- Q: 改密时路径账号不是操作人自己的账号，原先返回 403 `client_forbidden`；`client_forbidden` 随 clients 移除后怎么办？ → A: 改名为 `operator_forbidden`（仍 403，语义「操作人无权对该对象执行此操作」）（已确认，2026-10-27）。
- Q: Admin Center 与 UAM 各自是什么角色、访问方式是什么？ → A: Admin Center 是接入层中的 Web Server，登录成功后浏览器对它的访问基于会话；UAM 是 RESTful 的领域服务，对它的访问**不基于用户会话**，也不使用用户凭据（见 FR-008、FR-013）。
- Q: UAM 的 `validation_failed` 此前在「请求体缺字段」时返回 400、在「规则不符」时返回 422，同一个错误码对应两个状态码，要不要统一？ → A: 统一（已确认，选项 A，一个错误码对应一个状态码）：`validation_failed` 一律 HTTP 422（含请求体缺失 / 为空 / 过长字段、`Idempotency-Key`、分页与查询规则，仍带 `errors[{field, reason}]`）；无法解析或类型不符的请求（JSON 格式错误或为空、JSON 类型不对、路径变量或查询参数类型不符如非 UUID 的 id、`page=abc`）一律 HTTP 400，错误码 `bad_request`，不回显请求值；`operator_required` 仍为 400；其余状态码映射与响应结构不变（见 T198–T200）。

> **已移除：服务身份后续另行实现。** clients 功能（服务密钥、客户端清单、客户端权限、不停机轮换、拒绝日志）已整体移除；UAM 目前不认证调用方，只靠网络边界（UAM 仅对 Admin Center 开放）保护。本节原有的 7 条验收场景作废，编号与 [traceability](./traceability.md) 中的行保留为「已移除」占位，不再有对应实现与测试。后续服务身份（mTLS、平台身份、OAuth2 客户端凭据等）作为新特性立项时，在 `specs/` 中重新澄清需求。

## 功能需求

### FR-008（UAM 的访问不基于用户会话）

- **FR-008**: UAM 的访问 MUST 不基于用户会话：UAM MUST NOT 使用 cookie、会话标识、JWT 或任何用户凭据来识别或授权客户端；UAM 目前**不识别调用它的服务**（服务密钥已移除，服务身份后续另行实现，见 FR-042 ~ FR-044 占位），只靠网络边界保护（UAM 只对 Admin Center 实例开放）。Admin Center 代表已登录者发起查询与管理类调用时，MUST 把操作人（用户标识、账号标识、会话引用）作为请求数据明确传给 UAM；UAM 用它执行自我保护规则（不能停用自己、不能强制下线自己的会话、标注当前会话）与写操作日志，并信任网络边界内的调用方（即 Admin Center）所传的操作人；写操作缺少操作人时 UAM MUST 拒绝。会话标识 MUST 只作为「校验会话」「退出」的输入出现，不得用于调用 UAM 的其他能力。浏览器 MUST 只持有会话标识、MUST NOT 获得会话数据本身。

### UAM 职责（FR-013 ~ FR-015）

- **FR-013**: UAM MUST 是用户、账号、会话数据的唯一权威，并以 RESTful 领域服务的形式对外提供能力；Admin Center MUST 是基于会话的 Web Server，MUST NOT 保存或校验密码，也 MUST NOT 持久化用户、账号、会话数据。
- **FR-014**: UAM MUST 提供以下查询能力，供 Admin Center 调用：分页查询用户（含按用户名 / 账号名搜索）；查询单个用户及其关联的全部账号；分页查询当前在线用户；查询某个用户当前的全部有效会话。
- **FR-015**: UAM MUST 提供以下管理能力，供 Admin Center 调用：创建用户及其「账号名 / 密码」账号；停用 / 启用用户；终止指定会话；修改账号自己的密码（须验证当前密码）。管理能力的并发安全与规则校验 MUST 由 UAM 保证，不依赖 Admin Center。

### 服务客户端凭据（FR-042 ~ FR-044）

- **FR-042 ~ FR-044**: **已移除：服务身份后续另行实现。** 原要求 UAM 的每个接口携带并校验服务密钥（`client_unauthenticated`）、每个客户端有独立名称 / 至多两把密钥 / 权限（`client_forbidden`）、密钥可不停机轮换并提供生成工具与拒绝日志。clients 功能整体移除后，三条均无对应实现；UAM 只靠网络边界保护。后续另行实现服务身份时，再重新定义需求。

## Key Entities

- **会话数据（Session Data）**：UAM 校验有效会话后返回的信息，含用户标识、账号标识、会话引用与到期信息；Admin Center 据此得知操作人是谁，并在调用 UAM 时把操作人作为请求数据传入。它**不是**访问 UAM 的凭据；浏览器永远拿不到。
- **客户端（Client）**：**已移除**。原指调用 UAM 的服务及其服务密钥 / 权限（部署配置）；该概念随 clients 功能一并删除，UAM 不再有客户端实体或配置。

## Success Criteria

- **SC-016**: **已移除：服务身份后续另行实现。** 原要求无 / 错 / 已撤销密钥 100% 被拒绝、断言权限 100% 生效、轮换零意外登出、服务密钥零泄露；随 FR-042 ~ FR-044 一并作废。

## Edge Cases

- ~~服务密钥配置错误或轮换中途~~：已移除（不再有服务密钥）。

## Assumptions

- **会话数据与操作人**（已确认）：UAM 不使用 JWT 或任何用户凭据鉴权（参考图二里的 JWT 在本规格中不作为访问 UAM 的凭据）。会话数据是普通数据；Admin Center 对**每个**浏览器请求都向 UAM 校验会话标识，因此会话一结束，运维人员经 Admin Center 的下一次请求必定被视为未登录（FR-011、SC-013）。UAM 对写操作不再另行校验操作人的会话是否存活，而是信任调用方（Admin Center）传来的操作人。
- **UAM 暂不认证调用方**（已确认，取代原「UAM 的客户端与服务密钥」）：UAM 不基于用户会话，不使用任何用户凭据，**目前也不识别调用它的服务**——没有服务密钥、客户端清单、客户端权限与轮换。唯一的保护是网络边界：UAM 只对 Admin Center 实例开放（k8s NetworkPolicy / 内网 / VPN）。操作人由 Admin Center 以 `X-Operator-*` 请求头传入，UAM 信任它，仅用于自我保护、`current` 标注与写操作日志，**不用于认证或授权**。因此能直接连到 UAM 的任何一方都可以填写任意操作人：**必须**确保 UAM 不对 Admin Center 之外的任何方可达，这一约束在服务身份实现之前是硬性的部署要求。服务身份（如 mTLS、平台身份、OAuth2 客户端凭据）后续另行实现，不改接口形态与操作人请求头。
