## 概述（Admin Center 与 UAM 的分工、交互流程）

- **Admin Center（管理中心）**：接入层中的 **Web Server**，面向运维人员的浏览器入口。提供登录页、**User Manager（用户管理）** 与 **Session Manager（会话管理）** 两个管理界面，并在桌面、平板、手机上自适应。登录成功后，浏览器对它的访问**基于会话**（cookie 中的 session id）。它自己**不保存密码，也不保存用户、账号、会话数据**。
- **UAM（User Account Management，用户账号管理服务）**：**RESTful 的领域服务**，用户、账号、会话的**唯一权威**。负责校验登录凭据、签发并管理会话、维护用户与账号，并对客户端提供这些数据的查询与管理操作。对 UAM 的访问**不基于用户会话**：它不使用 cookie、会话标识或任何用户凭据来识别客户端；它只识别**调用它的服务**——每个接口调用都要带该服务的**静态服务密钥**；客户端把「操作人是谁」作为请求数据传入。

**交互流程**（来自参考图二）：

1. 浏览器携带 **cookie 中的 session id** 请求 Admin Center（Admin Center 一侧是基于会话的访问）。
2. Admin Center 向 UAM **校验 session id**，UAM 返回**会话数据**（用户、账号、会话引用、到期信息）。session id 只作为「校验会话」「退出」的**输入数据**出现，不是 UAM 识别客户端的方式。（参考图中这里是 JWT；本规格不把它用作访问 UAM 的凭据，见 Clarifications。）
3. Admin Center 此后代表该登录者向 UAM 发起服务调用（查询与管理操作）时，把**操作人**（用户、账号、会话引用）作为请求数据明确传给 UAM；**每个对 UAM 的调用都带 Admin Center 自己的服务密钥**，UAM 以此确认客户端是受信任的服务。UAM 一侧是**无会话、不使用用户凭据的 RESTful 访问**。
4. 浏览器始终只持有 session id，**拿不到会话数据本身**。

## Clarifications（技术性问答）

- Q: UAM 的网络范围是什么？ → A: UAM（领域服务）只在内网访问（已确认）；浏览器、公网与第三方碰不到 UAM。
- Q: UAM 要不要识别并限定客户端（服务间凭据）？ → A: 要（已确认，取代此前「本期不做」的回答）：本期就做**静态服务密钥**——每个客户端一把独立密钥、可不停机轮换、带权限；网络边界仍然要求，与服务密钥是两层保护。
- Q: UAM 要不要自己校验用户身份（把 UAM 当作接入层的、基于会话的服务）？ → A: 不要（已确认）：UAM 维持领域服务，不使用任何用户凭据，操作人由客户端以请求头传入。
- Q: 用户会话数据要不要用 JWT 作为访问 UAM 的凭据？ → A: 不用（已确认）。UAM 不基于用户会话，所以不使用用户凭据；它只识别调用它的服务（服务密钥）。操作人（用户、账号、会话引用）由客户端作为请求数据传给 UAM。
- Q: 调用 UAM 的服务用什么术语？ → A: 客户端（Client），不再用「调用方（Caller）」（已确认）。客户端指调用 UAM 的服务，不是浏览器；相应的标识符为 `client_unauthenticated`、`client_forbidden`、`UAM_CLIENTS`、`clientId`。
- Q: Admin Center 与 UAM 各自是什么角色、访问方式是什么？ → A: Admin Center 是接入层中的 Web Server，登录成功后浏览器对它的访问基于会话；UAM 是 RESTful 的领域服务，对它的访问**不基于用户会话**，也不使用用户凭据（见 FR-008、FR-013）。
- Q: UAM 的 `validation_failed` 此前在「请求体缺字段」时返回 400、在「规则不符」时返回 422，同一个错误码对应两个状态码，要不要统一？ → A: 统一（已确认，选项 A，一个错误码对应一个状态码）：`validation_failed` 一律 HTTP 422（含请求体缺失 / 为空 / 过长字段、`Idempotency-Key`、分页与查询规则，仍带 `errors[{field, reason}]`）；无法解析或类型不符的请求（JSON 格式错误或为空、JSON 类型不对、路径变量或查询参数类型不符如非 UUID 的 id、`page=abc`）一律 HTTP 400，错误码 `bad_request`，不回显请求值；`operator_required` 仍为 400；其余状态码映射与响应结构不变（见 T198–T200）。

## User Story 12 - UAM 只接受持有服务密钥的受信任客户端（Priority: P2）

运维团队部署时为 Admin Center 生成一把服务密钥：UAM 的每个接口调用都必须带上它，否则被拒绝。需要换密钥时可以不停机轮换。

**Why this priority**: 本期 UAM 不使用任何用户凭据，信任来自「谁在调」；没有它，能连上 UAM 的任何人都能冒充运维人员。应在首次上线之前具备，但它不阻塞用户与会话管理本身的功能，所以排在 P1 之后。

**Independent Test**: 用生成工具生成密钥并配置；不带密钥直接调 UAM 任一接口被拒；带错密钥被拒；Admin Center 带正确密钥时全部功能正常；做一次轮换，期间用户无感。

**Acceptance Scenarios**:

1. **Given** UAM 已配置 Admin Center 的密钥，**When** Admin Center 带正确密钥调用任何接口，**Then** 正常处理。
2. **Given** UAM 的任一接口，**When** 不带密钥、带错误密钥或带已撤销的旧密钥调用，**Then** 被拒绝（401），响应不透露哪里不对，且不执行任何操作。
3. **Given** 一个密钥有效但未被授予「可代用户断言操作人与来源地址」权限的客户端，**When** 调用登录、校验会话、退出、修改密码或任何写操作，**Then** 被拒绝（403）；只读查询仍可调用。
4. **Given** 轮换开始，新旧两把密钥同时有效，**When** Admin Center 切换到新密钥后撤销旧密钥，**Then** 全程没有用户被登出、没有请求因密钥而失败；撤销之后旧密钥被拒绝。
5. **Given** Admin Center 配置的密钥错误（配置失误），**When** 已登录用户访问页面，**Then** 用户不被登出、cookie 不被清除，页面提示服务暂不可用，运维能看到告警日志；修正配置后无需重新登录。
6. **Given** 部署时，**When** 运行生成工具，**Then** 它只输出密钥一次并给出对应的哈希；UAM 配置里只有哈希；Admin Center 缺少密钥时启动失败。
7. **Given** 任何页面、响应与日志，**When** 检查内容，**Then** 都不出现服务密钥；被拒绝的调用有记录（来源、时间、原因类别，不含密钥）。

## 功能需求

### FR-008（UAM 的访问不基于用户会话）

- **FR-008**: UAM 的访问 MUST 不基于用户会话：UAM MUST NOT 使用 cookie、会话标识、JWT 或任何用户凭据来识别或授权客户端；UAM 只通过**服务密钥**识别调用它的服务（见 FR-042 ~ FR-044）。Admin Center 代表已登录者发起查询与管理类调用时，MUST 把操作人（用户标识、账号标识、会话引用）作为请求数据明确传给 UAM；UAM 用它执行自我保护规则（不能停用自己、不能强制下线自己的会话、标注当前会话）与写操作日志，并信任**已通过服务密钥校验、且被授予断言权限**的客户端所传的操作人；写操作缺少操作人时 UAM MUST 拒绝。会话标识 MUST 只作为「校验会话」「退出」的输入出现，不得用于调用 UAM 的其他能力。浏览器 MUST 只持有会话标识、MUST NOT 获得会话数据本身。

### UAM 职责（FR-013 ~ FR-015）

- **FR-013**: UAM MUST 是用户、账号、会话数据的唯一权威，并以 RESTful 领域服务的形式对外提供能力；Admin Center MUST 是基于会话的 Web Server，MUST NOT 保存或校验密码，也 MUST NOT 持久化用户、账号、会话数据。
- **FR-014**: UAM MUST 提供以下查询能力，供 Admin Center 调用：分页查询用户（含按用户名 / 账号名搜索）；查询单个用户及其关联的全部账号；分页查询当前在线用户；查询某个用户当前的全部有效会话。
- **FR-015**: UAM MUST 提供以下管理能力，供 Admin Center 调用：创建用户及其「账号名 / 密码」账号；停用 / 启用用户；终止指定会话；修改账号自己的密码（须验证当前密码）。管理能力的并发安全与规则校验 MUST 由 UAM 保证，不依赖 Admin Center。

### 服务客户端凭据（FR-042 ~ FR-044）

- **FR-042**: UAM 的**每一个**接口调用 MUST 携带服务密钥（HTTP 请求头）并由 UAM 校验；缺失、无效或已被撤销的密钥 MUST 被拒绝（`client_unauthenticated`），且不透露是哪一部分不对。UAM MUST 以不泄露密钥信息的方式比较密钥，MUST 只保存密钥的不可逆哈希，MUST NOT 在任何响应、页面或日志中出现密钥；被拒绝的调用 MUST 记录（来源、时间、原因类别，不含密钥）。
- **FR-043**: 每个客户端 MUST 有独立的名称、至多两把同时有效的密钥和权限。只有被授予「可代用户断言操作人与来源地址」权限的客户端，才可调用登录、校验会话、退出、修改密码与所有写操作；未被授予的客户端调用这些接口 MUST 被拒绝（`client_forbidden`），但可以调用只读查询。本期只有 Admin Center 被授予该权限。
- **FR-044**: 服务密钥 MUST 支持**不停机轮换**：新旧两把密钥可同时有效，客户端切换到新密钥并确认后再撤销旧密钥，期间没有任何用户被登出、没有任何请求因密钥而失败。系统 MUST 提供生成密钥及其哈希的工具（密钥只输出一次）；Admin Center 缺少密钥时 MUST 启动失败；UAM 因密钥不匹配拒绝 Admin Center 时，Admin Center MUST 视为「服务暂不可用」（不登出用户、不清除 cookie），并产生运维可见的告警日志。

## Key Entities

- **会话数据（Session Data）**：UAM 校验有效会话后返回的信息，含用户标识、账号标识、会话引用与到期信息；Admin Center 据此得知操作人是谁，并在调用 UAM 时把操作人作为请求数据传入。它**不是**访问 UAM 的凭据，UAM 不因它识别客户端；浏览器永远拿不到。
- **客户端（Client）**：调用 UAM 的服务（**不是浏览器**），本期只有 Admin Center。有名称、至多两把同时有效的服务密钥（轮换用）和权限（本期仅「可代用户断言操作人与来源地址」）。它是部署配置，不是业务数据，不在 UAM 的数据库里。

## Success Criteria

- **SC-016**: 不带密钥、带错密钥或带已撤销密钥的调用，在 UAM 的全部接口上 100% 被拒绝；未被授予断言权限的客户端调用登录、校验会话、退出、修改密码与写操作 100% 被拒绝；一次密钥轮换的全过程中，意外登出的用户数为 0、因密钥而失败的请求数为 0；服务密钥出现在页面、响应与日志中的次数为 0。

## Edge Cases

- **服务密钥配置错误或轮换中途**：Admin Center 的密钥与 UAM 不匹配时，已登录用户不被登出、cookie 不清除，页面显示「服务暂不可用」并产生告警日志；这种情况**不得**被当作「会话无效」。

## Assumptions

- **会话数据与操作人**（已确认）：UAM 不使用 JWT 或任何用户凭据鉴权（参考图二里的 JWT 在本规格中不作为访问 UAM 的凭据）。会话数据是普通数据；Admin Center 对**每个**浏览器请求都向 UAM 校验会话标识，因此会话一结束，运维人员经 Admin Center 的下一次请求必定被视为未登录（FR-011、SC-013）。UAM 对写操作不再另行校验操作人的会话是否存活，而是信任客户端传来的操作人。
- **UAM 的客户端与服务密钥**（已确认）：UAM 不基于用户会话，不使用任何用户凭据，只识别调用它的服务。本期用**静态服务密钥**：每个客户端一把（轮换期间至多两把）长随机密钥，UAM 的配置里只保存其哈希，客户端把它放在自己的密钥存储里。网络边界仍然要求（UAM 只对 Admin Center 实例开放），与服务密钥一起构成两层保护。将来可以换成更强的服务身份（如传输层身份）而不改接口形态与操作人请求头。服务密钥一旦泄露就等于客户端被冒充（持有者可以填写任意操作人），请把它当作与数据库密码同级的机密。

| SC-013 | **SC-013**: 会话因任何原因结束（退出、到期、被取代、被强制下线、用户被停用）后，在任一实例上用其会话标识发起的下一次请求 100% 被视为未登录；Session Manager 刷新后 100% 不再显示该会话。 |
| SC-014 | **SC-014**: 在所有页面、接口响应与日志的抽查中，出现明文密码（含新建用户的初始密码、修改密码时的当前密码与新密码）、密码哈希、机密会话标识、会话数据本身的次数为 0；跨站伪造的写请求 100% 被拒绝；每次写操作 100% 留有含操作人、对象、动作、时间、结果的日志记录。 |
| Edge Cases · UAM 暂时不可用 | **UAM 暂时不可用**：带会话 cookie 的请求到达 Admin Center，但 UAM 超时或不可达。受保护页面显示「服务暂不可用，请稍后重试」，**不清除 cookie、不当作已退出**；UAM 恢复后无需重新登录即可继续。写操作在此期间失败时，明确提示「操作未生效」，不得显示为成功。 |
| Edge Cases · 会话标识被篡改或不存在 | **会话标识被篡改或不存在**：视为未登录，带到登录页，清除该 cookie。 |
| Assumptions · 修改密码后的会话 | **修改密码后的会话**：修改成功后当前会话保持有效；会话标识是否轮换等细节留给 plan。因账号与会话一一对应，被修改密码的账号不存在需要另行处理的其他会话。 |
| Assumptions · 部署边界 | **部署边界**（已确认）：UAM 只在内网访问；Admin Center 与 UAM 默认只在内网 / VPN 内可达，具体网络配置属于部署；应用层安全不因此放松。 |
| Assumptions · 本期范围外 | **本期范围外**：第三方（如 OIDC）登录、短信 / 邮件验证、账号种类扩展的实际实现、权限与角色、可查询的审计记录与审计界面（本期仅写应用日志）、上述「写操作范围」中未列入的操作、业务系统与多身份域、SSO、更强的服务身份（如 mTLS、平台身份、OAuth2 客户端凭据）、头像、忘记密码找回、运维人员重置他人密码。设计不得阻碍它们日后加入，但本期不做。 |
