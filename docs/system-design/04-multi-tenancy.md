# 04 多租户

状态：设计基线（尚未落地）。说明租户注册、cell 部署形态、入口路由、开通与暂停、模块授权。决策见 [06](06-decisions.md)，待定项也在 06；正文标“待定”的地方，实现时不得自行假设。

## 1. 租户注册表

归属：Platform Service（平台级服务，在平台 cell），是租户的唯一事实来源。

| 字段 | 说明 |
|---|---|
| `tenant_id` | 租户唯一标识，由所属 cell 的 UAM 写入内部 JWT |
| 名称、状态 | 状态至少包括：开通中、正常、暂停 |
| 部署形态 | pool 或 silo |
| `cell_id` | 租户所在的 cell |
| 已开通模块 | 模块授权（entitlement），见 5 |

注册表通过事件传播到租户 cell（见 05），平台 cell 不同步调用租户 cell。

## 2. 平台租户、pool 与 silo

**平台租户**是特殊的保留租户（D26）：独立的平台 cell，自带网关、Tenant Core（含 UAM）、数据库与审计；平台级服务是它的模块。它不经日常开通流程创建，见 3.1。

| | pool | silo |
|---|---|---|
| 服务 | 多个租户共用同一组业务级服务 | 该租户独占一组服务 |
| 数据库 | 共享库，按 `tenant_id` 隔离（如 RLS） | 独占库 |
| 网关与 UAM | 该 pool cell 自己的一套，UAM 多租户 | 独占 cell 自己的一套 |
| 入口 | 租户域名指向 pool cell 的网关 | 租户域名指向该租户 cell 的网关 |

前期租户不超过 5 个，可全部按 pool 部署，silo 作为能力预留；边界（`tenant_id` 隔离、每个 cell 一套网关与 UAM）从一开始就按两种形态通用来定。

**入口路由**：每个 cell 有自己的网关，网关只按路径路由到本 cell 的服务（D28）。租户如何到达所属 cell 的网关在 cell 之外解决，倾向每租户一个域名或子域名、由 DNS 指向所属 cell，待定。

## 3. 租户开通

### 3.1 冷启动（CLI）

平台租户和它的模块授权由 CLI 写入（D23）：平台 UAM 的第一个 staff（及其在平台 Tenant Core 的档案）、平台租户记录、模块授权；全新环境里也可用 CLI 在租户 cell 创建初始租户与第一个管理员。之后才由 Platform Service 管理，CLI 写入的记录要与租户注册表对账（待定）。CLI 不替代下面的日常开通。

### 3.2 日常开通

```text
平台管理员 → Platform BFF → Platform Service
    1. 写租户注册表（开通中），同一事务写 outbox
    2. 发布“租户开通请求”事件
租户 cell 订阅事件，各自完成自己的部分：
    UAM：创建租户记录与登录配置（第一阶段为用户名密码）、第一方 client（BFF、桌面端）
    租户核心模块：初始化租户配置与默认角色
    （silo）部署独占 cell：网关、服务、数据库、Tenant Core
各自完成后发布“完成”事件 → Platform Service 汇总后把状态改为“正常”
```

首个租户管理员的创建方式、开通失败的补偿与重试待定。

## 4. 租户暂停

- Platform Service 把状态改为“暂停”并发布事件。
- 租户 cell 的 UAM 拒绝签发与刷新令牌，并吊销该租户已有的令牌，网关下一次校验即拒绝（吊销方式待定）；已换发的内部 JWT 最多再存活到 `exp`。
- 租户核心模块更新只读投影，业务级服务通过权限查询接口得到租户状态，对暂停的租户拒绝请求。

## 5. 模块授权（entitlement）

- Platform Service 维护租户与模块的授权关系，变更通过事件投影到各 cell 的租户核心模块（只读）。
- 业务级服务按租户查询权限接口，同一次查询得到角色、租户状态与已开通模块；模块未开通时拒绝该租户的请求，网关不判断。
- 平台租户自己的模块授权由 CLI 冷启动写入。

## 6. 数据边界

- 租户用户和租户内部数据对平台侧不可见：档案在租户 cell 的 Tenant Core，凭证、身份绑定与令牌在租户 cell 的 UAM，审计在租户 cell 的 Audit。
- 平台侧只持有租户注册表、模块授权，以及平台 cell 自己的 staff 档案、UAM 数据与审计；不能访问租户 cell 的数据库，两个 cell 之间 NetworkPolicy 互相拒绝。
- 平台级数据分析的数据来源与边界实现时再定，须守住上述边界。
- 任何服务写入或查询租户数据时，`tenant_id` 来自内部 JWT 或事件，不取自请求参数。
