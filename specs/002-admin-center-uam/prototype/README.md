# Admin Center 界面设计原型

**Feature**: [spec.md](../spec.md)（FR-041、User Story 11、SC-015） | **Plan**: [plan.md](../plan.md) | **Date**: 2026-10-23 | **状态**: 已确认（2026-10-23，用户已确认技术栈与本原型）

一份**零依赖、可点击**的静态原型，用来在界面实现之前评审页面、交互与关键状态。**它不是生产代码，也不会被实现复用**；所有数据都是内存里的合成假数据，刷新即重置，不发任何网络请求。

> **评审门禁**：按 spec FR-041，界面实现必须在用户确认这份原型之后才开始。**状态：已确认（2026-10-23）**——技术栈与本原型均已由用户确认，界面实现已据此开展；实现与原型的一致性由 `apps/admin-center/tests/e2e/us11-*.spec.ts` 核对（见 tasks.md Phase 13）。

## 怎么看

任何浏览器直接打开 `index.html` 即可（不需要安装任何环境）：

```bash
open specs/002-admin-center-uam/prototype/index.html
```

- 顶部**视口**按钮：桌面 1280 / 平板 820 / 手机 390 / 最窄 320。布局按真实 CSS 宽度渲染，窗口较窄时整体缩放显示。
- 顶部**场景**下拉：切换到各种状态（见下表）；「重置数据」还原假数据。
- `app.html` 是真正的响应式界面，也可以单独打开、自己拖动浏览器窗口宽度，或在后面加 `?scenario=uam-down` 之类的参数。

## 场景

| 场景（`?scenario=`） | 展示什么 | 对应 spec |
|---|---|---|
| `normal` | 全部页面与可操作流程：新建用户（含校验错误、账号名冲突）、停用 / 启用（含确认）、强制下线（含确认、自己的当前会话被禁用）、修改密码（含各类校验）、退出 | FR-017 ~ FR-033 |
| `empty` | 没有用户、没有在线用户的空状态 | FR-020、FR-028 |
| `uam-down` | 顶部「服务暂不可用」横幅、列表换成错误状态、保留登录状态；任何写操作提示「操作未生效」，绝不显示成功；UAM 因服务密钥配置错误拒绝 Admin Center 时也是这个界面（不登出用户） | FR-009、FR-033、FR-044 |
| `session-ended` | 会话已结束 → 登录页提示「会话已结束，请重新登录」；受保护页面访问会被带回登录页 | FR-009、FR-011、FR-012 |
| `force-logged-out` | 被强制下线 → 登录页提示「你的会话已被管理员强制下线」 | FR-011、FR-030 |
| `session-gone` | 强制下线时会话恰好已自行结束 → 提示「该会话已结束，已刷新为最新状态」，不报错 | FR-030 |
| `last-active-user` | 「不能停用最后一个正常用户」的禁用说明（真实情况下只在并发操作时出现，这里为展示设计） | FR-025 |

## 覆盖的页面与状态（对照 FR-041）

| 要求 | 在原型里 |
|---|---|
| 登录页 | `#/login`：必填提示、统一失败提示、限流提示、会话结束 / 被下线提示 |
| 导航外壳（桌面 / 平板 / 手机） | 桌面侧边栏展开、平板图标条、手机抽屉（汉堡按钮，`Esc` 关闭并回到按钮）；顶栏用户菜单含「修改密码」「退出登录」；面包屑 |
| User Manager 列表 | `#/users`：搜索（用户名或账号名，大小写不敏感）、分页（原型每页 6 条）、状态徽标、关联账号数；手机上变卡片 |
| 新建用户表单 | `#/users/new`：用户名 / 账号名 / 初始密码，字段级校验、账号名冲突、不回填密码 |
| 用户详情（含账号、停用 / 启用） | `#/users/u2`（两个账号）、`#/users/u5`（无账号空状态）、`#/users/u4`（已停用）、`#/users/nope`（用户不存在）；停用 / 启用的确认对话框；停用自己被禁用并说明 |
| Session Manager 在线用户列表 | `#/sessions`：用户名、有效会话数、最近活动；空状态 |
| 用户会话详情（含强制下线） | `#/sessions/u2`（两个会话）；每条含账号及种类、登录 / 最近活动 / 到期时间、会话引用（**不显示会话标识**）；「当前会话」标注与禁用说明；强制下线确认；全部下线后的空状态 |
| 修改密码 | `#/account/password`：当前密码 / 新密码 / 确认，各类校验与成功提示；当前会话保持有效 |
| 关键状态 | 登录失败、空列表、用户无账号、无在线会话、会话已失效或被强制下线、UAM 暂不可用、表单校验与冲突、停用 / 强制下线确认、不可停用 / 不可下线说明 —— 全部可在上表场景中看到 |

## 刻意没有的东西（spec 范围外）

编辑用户名、删除用户、运维人员重置他人密码、忘记密码找回、为已有用户添加 / 解绑账号、单个账号的停用 / 启用、批量或按用户一键下线、审计日志查看页、权限与角色。评审时若发现原型里出现这些入口，请当作缺陷指出。

## 评审要点（请重点看）

1. 导航与信息架构：「用户管理」「会话管理」两个入口，用户菜单里的「修改密码」「退出登录」，是否符合预期。
2. 各页面的信息项是否够用（列表列、详情字段、会话字段）。
3. 破坏性操作（停用、强制下线）的确认文案与禁用说明是否清楚。
4. 手机、平板上的呈现（卡片、抽屉、对话框）是否可接受。
5. 空状态与错误状态的措辞。

## 技术说明

- `index.html`：查看器（视口与场景切换，把 `app.html` 放进对应宽度的框里）。
- `app.html` + `styles.css` + `app.js`：界面本体。哈希路由；所有渲染对用户输入做转义；对话框带焦点限制与 `Esc` 关闭；尊重 `prefers-reduced-motion`，并带深色模式样式。
- 已在真实浏览器中核对：320 / 375 / 768 / 1024 / 1440 / 2560 六个宽度 × 11 个路由共 66 项检查，无整页横向滚动；各宽度的布局模式（手机抽屉 / 平板图标条 / 桌面展开）切换正确，320 宽下对话框完整可见；上述场景与交互流程用脚本逐条断言通过。尚未做的：屏幕阅读器实测与真机触控实测（评审时请留意）。
