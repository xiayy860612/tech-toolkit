# Quickstart: Tenant Admin Center 验证指南

**Feature**: [spec.md](spec.md) · **Contract**: [contracts/openapi.yaml](contracts/openapi.yaml) · **Data model**: [data-model.md](data-model.md)

本文是端到端**验证场景**，不含实现代码。`backend/`、`frontend/` 尚未创建；启动/构建/测试的具体命令将在实现阶段写入各自的 `AGENTS.md`，此处只写前置条件与预期结果。

## 前置条件

- JDK 21、Node.js 22 + pnpm、Docker（PostgreSQL 与 Testcontainers）。
- 本地通过同域入口访问：浏览器访问 Next.js BFF；BFF 持有**后端签发**的会话令牌（Cookie），经后端解析会话后签发内部 JWT 调用仅内网可达的后端（无 CORS）。需要 Redis（仅 BFF 限流）与一对开发用 Ed25519 密钥（由脚本生成，不入库）。
- 已用 `bootstrap` 命令在默认租户（`tenant-id = 0`）预置一名管理员，临时密码由命令输出一次；需要第二个租户的场景（12、18、19）使用**测试夹具**另建租户 1（本期无租户管理，租户 1 仅存在于测试环境）。以下 `<…>` 为占位。

## 场景（对应 spec 的 User Story 与 Success Criteria）

| # | 场景 | 步骤 | 预期 | 覆盖 |
|---|------|------|------|------|
| 1 | 默认租户 | 打开 `/login` 提交凭证（无租户入口、无租户编码输入） | 登录请求归入默认租户 `tenant-id = 0`；登录页没有任何租户相关输入 | US1-1、FR-015 |
| 2 | 首次登录强制改密 | 在登录页用管理员用户名 + 临时密码登录 | 被导向改密页；改密前访问其他页面均回到改密页；改密后进入用户列表 | FR-011a、US1-3 |
| 3 | 登录失败不泄露 | 分别输入：不存在的用户名、错误密码、停用用户、被锁定用户 | 全部提示"用户名或密码错误"，响应体一致；审计日志中原因各异 | FR-007、US1-4/5 |
| 4 | 锁定与解锁 | 同一用户连续输错 5 次，再输正确密码；管理员在详情页解锁后重试 | 锁定期间正确密码也被拒；解锁后可登录；两事件入审计 | FR-008/008a、US3-1 |
| 5 | 创建用户 | 管理员新建用户（留空密码让系统生成）→ 记下一次性临时密码 | 列表出现该用户；新用户用临时密码登录后被强制改密；2 分钟内可完成 | US2-1、SC-002 |
| 6 | 用户名冲突 | 再建同名用户；换到租户 1（夹具）建同名 | 租户 0 内 409 `USERNAME_TAKEN`；租户 1 内成功 | US2-2、US4-3、FR-014 |
| 7 | 用户名密码内置于 User | 创建用户（接口必须带用户名与密码）；在用户详情页查看「登录账号」区；确认没有 Account 列表与「新增 Account」入口 | 每个用户必然有用户名与密码（数据库列非空）；详情页只展示用户名、锁定状态、最近登录，操作仅解锁与重置密码；其他登录方式（手机号、微信、OAuth2.0）及"每类型至多一个"待第二种类型落地后验证（SC-004） | US3-3、FR-001/002、SC-004 |
| 8 | 主键与公开标识 | 检查接口返回：用户 id 为整数；会话 id 为 UUID；`/auth/me`、会话列表不含 `accountId` | user、审计 id 为递增整型；会话 id 不可枚举 | FR-004a |
| 9 | 重置密码 | 管理员重置某用户密码 | 旧密码失效、该用户会话立即失效、下次登录强制改密 | US3-2、FR-010 |
| 10 | 停用用户 | 停用一个已登录用户 | 该用户无法再登录，已有会话下一次请求即 401 | US2-3、FR-019 |
| 11 | 守卫 | 管理员停用自己；修改自己的角色；停用/降级最后一名管理员 | 409 `CANNOT_DISABLE_SELF` / `CANNOT_CHANGE_OWN_ROLE` / `LAST_ADMIN`；界面对自己不显示「停用」、角色选择禁用；管理员仍可重置自己的密码 | FR-021、FR-021a |
| 12 | **跨租户隔离** | 用租户 0 管理员会话，按租户 1 用户的 id 调用读、改、停用、解锁、重置密码；列表与搜索 | 全部 404（与不存在不可区分）；列表只含 acme；0 泄露 | US4、SC-003、FR-013/025 |
| 13 | 越权、降级与跨站写 | 普通用户（MEMBER）登录；管理员被降级后用原会话再访问管理接口；`Origin` 不匹配的写请求发往 BFF | MEMBER 被导向 `/forbidden`，访问管理接口 403 `FORBIDDEN`；降级后下一次请求即 403（角色以数据库为准）；跨站写被 BFF 拒绝 | FR-022、R5 |
| 14 | 会话超时与失效 | 缩短空闲/绝对超时后等待；另：管理员重置某用户密码后，该用户原会话再发请求 | 过期后请求 401，BFF 清除 Cookie，页面回到 `/login` 并保留 `next`；重置后原会话已被后端撤销，下一次请求即 401 | FR-010、Edge Case |
| 15 | 并发编辑 | 两个管理员同时编辑同一用户后先后提交 | 后提交者 409 `VERSION_CONFLICT`，前端提示刷新 | Edge Case |
| 16 | 审计覆盖 | 完成以上场景后查询 `GET /audit-logs` | 登录成功/失败、锁定/解锁、全部管理操作均有记录，字段含操作者、对象、时间、结果；无任何密码/令牌 | FR-023、SC-006 |
| 17 | 性能 | 租户内预置 1,000 用户 + 100 并发管理员会话压测列表与搜索 | p95 ≤ 2 秒 | SC-005 |
| 19 | **会话管理** | 同一用户在两个浏览器各登录一次，另一用户再登录一次；管理员打开「会话管理」页，按用户筛选，强制下线其一，再「下线该用户全部会话」；管理员对自己的会话/用户重复；用租户 0 管理员构造租户 1 的 会话 id/`userId` 请求；停用某用户后刷新页面 | 列表显示本租户全部有效会话（含用户、用户名、设备、IP、时间）；被下线的浏览器下一次请求即 401 并回到登录页，其余不受影响；自己的当前会话标「当前」且不可下线、自己的用户行无「下线该用户全部会话」；跨租户引用一律当作不存在、租户 1 会话不受影响；被停用用户的会话不再出现；审计含 `SESSION_REVOKED`/`SESSIONS_REVOKED_ALL` | US5、FR-026–030、SC-008 |
| 18 | **内部凭证校验** | 绕过 BFF 直连后端：无 JWT、过期 JWT、错误密钥签发的 JWT、`alg=none`；以及在 BFF 请求里自带 `X-Tenant-*`/`tenantId` | 直连一律 401；浏览器侧租户标识被忽略，租户只取自 JWT | FR-024a、FR-025、R16 |

## 通过标准

- 场景 1–16、18、19 全部通过；场景 12 为 100% 通过的硬门禁（任何泄露即失败）。
- 单元测试行覆盖率：`backend/`、`frontend/` 各 ≥ 90%（根 AGENTS.md Quality gates）。
- 后端响应均通过 `contracts/openapi.yaml` 校验；前端 API 类型由该契约生成，无手写偏离。
- 自动化分层：能单测的单测（锁定策略、判定顺序、密码规则、不变量守卫）；RLS/迁移/会话/跨租户隔离用 Testcontainers 集成测试；场景 1、2、5、7、12 作为 Playwright E2E 关键旅程。
